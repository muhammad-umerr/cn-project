FTP/NAT — Packet Evidence Index (24 November 2026)
=================================================
Source: FTP_NAT_Packet_Evidence.zip uploaded by the team.
18 scenario PCAPNG files (6 scenarios × 3 capture points), plus 3 manual-test PCAPNG files.
The packet-derived figures in the report are not screenshots of the Wireshark application.
For the instructor's annotated screenshot requirement, capture the original frames in Wireshark and add annotations.

Capture locations:
  r1-inside  = ftp-client side of R1, before source NAT
  r1-outside = transit side of R1, after source NAT
  r2-server  = server-side interface of R2

1) 01_control_handshake_login
   r1-inside: FTP 220, USER, 331, PASS, 230 and TCP SYN from 192.168.10.2:46034 to 172.16.20.10:21
   r1-outside: corresponding client control source translated to 10.0.12.1:46034.

2) 02_passive_pasv_N1
   server sends PASV 227 (172,16,20,10,156,153): 172.16.20.10:40089
   data SYN inside 192.168.10.2:34120 -> 172.16.20.10:40089
   data SYN outside 10.0.12.1:34120 -> 172.16.20.10:40089
   LIST: 150, 226; RETR: 150, 226.

3) 03_active_port_N1_data_fails
   inside and outside FTP payload: PORT 192,168,10,2,138,243 (port 35571)
   outside IP header source translated to 10.0.12.1, payload private IP unchanged.
   FTP server responds 500 Illegal PORT command. No data TCP SYN in this capture.

4) 04_active_port_N2_helper
   inside payload: PORT 192,168,10,2,154,107 (port 39531)
   outside payload: PORT 10,0,12,1,154,107 (port 39531)
   server replies 200 PORT command successful.
   data TCP SYN: server 172.16.20.10:20 -> 10.0.12.1:39531 (outside),
             server 172.16.20.10:20 -> 192.168.10.2:39531 (inside).
   LIST and RETR: 150, 226.

5) 05_passive_no_nat_N0
   PASV 227 and client initiated SYN to TCP 40097 (directory listing), TCP 40035 (download).

6) 06_active_no_nat_N0
   PORT negotiation and server-originated TCP SYN from 172.16.20.10:20 to 192.168.10.2:34061 (LIST)
   and to port 34007 (RETR).

Suggested Wireshark display filters:
  tcp.port == 21
  ftp.request.command == "PORT"
  ftp.request.command == "PASV"
  tcp.flags.syn == 1 && tcp.flags.ack == 0
  tcp.analysis.retransmission

Security: FTP PASS commands contain plaintext lab credentials. Rotate the lab password or redact
credential packets before making captures publicly accessible on GitHub. Preserve original
restricted copies for your instructor where appropriate.

PROTOCOL FUNDAMENTALS

Why do FTP and NAT interact?

① Control connection

Both modes establish an outgoing TCP connection from the client to the server's TCP port 21. Commands USER, PASS, LIST, RETR and STOR travel here. Login success proves only control connectivity.

② Active FTP · PORT

The client listens on a port and includes its IP and port in a PORT command. The server initiates a separate TCP data connection back to that address. Plain source NAT does not necessarily rewrite the address in PORT.

③ Passive FTP · PASV

The server announces a reachable data port; the client opens the data connection. Outgoing client-originated TCP data connections normally traverse source NAT more easily.

④ N2 helper

nf_conntrack_ftp parses the cleartext FTP control stream; with nf_nat_ftp it can rewrite embedded addresses and establish expected RELATED data flows. Verify packets and expectations: helper behavior is not assumed.

⑤ Packet loss

Linux tc netem applies independent configured packet-loss probabilities on both sides of the transit link. tc tbf limits throughput. Observe retransmissions and report measured mean, SD, and range.

⑥ Evidence-first conclusions

Show both sides of R1, the source IP transformation, and which host sends the data-connection SYN. A 230 FTP reply alone does not prove the data channel worked.

Why

Control connection always works: the client opens it outbound, so NAT creates state on the first SYN.

Active, N1: the PORT command carries the private address 192.168.10.2. NAT only rewrites headers, so the server tries to connect to an address R2 cannot route. The data connection fails.

Active, N2: nf_conntrack_ftp reads PORT, rewrites it to 10.0.12.1, and creates an expectation, so the server's inbound SYN is translated back to the client.

Passive: the client opens the data connection outbound to the port in the 227 reply (40000–40100), so ordinary masquerading is enough.

N0 assumes the return route to 192.168.10.0/24 is added on R2, as the proposal notes.
